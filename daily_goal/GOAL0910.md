## 1. 목표와 산출물

LAB1의 조합회로 10개를 구현하는 매뉴얼을 세 버전으로 만들고, **같은 저장소에 프로젝트 22개와 프로젝트별 VS Code workspace 22개**를 구성한다. 같은 회로와 예상 동작을 다루되 도구와 독자의 숙련도에 맞춰 설명한다. 이 문서는 제작 목표이며 아래 예정 경로와 체크리스트는 구현 완료를 뜻하지 않는다.

**수업의 전체 목표는 VS Code에서 먼저 시뮬레이션하여 실험 전 레포트에 자세히 기록하고, 실험에서는 Vivado 시뮬레이션과 실제 FPGA 비트스트림 기록·동작 확인까지 수행한 뒤 사진·영상·코드·결과를 GitHub에 올려 실험 후 레포트에서 설명하는 것이다.** 프로젝트와 매뉴얼은 이 흐름을 끝까지 지원해야 한다.

| 프로젝트 구분 | 개수 | 용도 |
|---|---:|---|
| 레거시 Vivado 개별 프로젝트 | 10 | 원본 교안의 회로별 실습 재현 |
| Vivado 2026.1 개별 프로젝트 | 10 | 최신 도구로 회로별 실습 |
| Vivado 2026.1 통합 프로젝트 | 1 | 버튼으로 10개 회로의 모드를 순환하고 LCD에 현재 모드 표시 |
| 오픈소스 CLI 통합 프로젝트 | 1 | 같은 통합 RTL을 CLI로 빌드하여 비트스트림 생성 |
| **합계** | **22** | **프로젝트마다 전용 `.code-workspace` 제공** |

- 목차 원본: `weekly-slides/weekly-slides/LAB1_FPGA_0914/04.LAB1_00_CONTENTS.tex`
- 실습별 원본은 `04.LAB1_01_XXXX.tex` 형식으로 만든다. 최신 첫 파일은 `04.LAB1_01_LOGIC_GATES_VIVADO.tex`, 레거시 첫 파일은 `04.LAB1_11_LOGIC_GATES_LEGACY.tex`이며 교육 번호·회로명·도구 버전을 구분한다.
- 각 TeX와 같은 이름으로 PDF를 만든다. 학생 배포는 **목차 PDF + 실습별 PDF를 함께 묶은 ZIP**으로 제공한다. 첫 배포 묶음은 `04.LAB1_0910_PDF.zip`으로 구성한다.
- 자료 작성일은 **2026-09-10**이며 표지에도 작성일을 표시한다. **2026-09-14 수업 전에 학생들이 예습할 자료**이므로 표지 날짜를 수업일로 대체하지 않는다.
- 배포·전체 목차 순서: **A. Vivado 2026.1 → B. 오픈소스 CLI → C. 레거시 Vivado**. 각 자료 내부에서는 VS Code 사전 시뮬레이션과 실험 전 레포트를 먼저 마친다.
- 본문·서식은 공통 TeX 파일을 불러와 재사용한다. 학생용 파일은 목차와 실습 단위로 나누며 중복된 `04.LAB1_COMB_0910.tex`·PDF는 유지하지 않는다.
- 함께 제공할 자료: 회로 소스, 테스트벤치, 보드 제약 파일, 실행 스크립트, 실제 화면 캡처, 실험 전·후 레포트 작성 틀과 예시, GitHub 결과 정리 안내.
- 강의 내용의 원본은 TeX다. LAB1은 [4:3 공용 Beamer 템플릿](../weekly-slides/templates/weekly_presentation_template_4x3.tex)을 사용한다. 기존 로고·색상·폰트를 유지하고 리소스는 상대경로로 연결한다. 기존 16:9 템플릿도 별도로 보존한다.
- **슬라이드용 PNG는 로컬 빌드 자료로 두고 앞으로 Git에서 무시한다.** 이미 추적 중인 PNG는 굳이 제거하지 않는다. PDF는 계속 커밋하며, 다른 장치에서 clone한 뒤 TeX를 다시 빌드할 수 있어야 한다는 요구는 두지 않는다. 학생용 HDL 프로젝트·workspace의 실행 경로 검증은 별개로 유지한다.
- **레거시를 제외한 슬라이드의 소스코드는 사용자의 편집기 테마가 적용된 실제 VS Code 화면을 캡처한 이미지로 넣는다.** PDF에서 코드를 드래그하여 바로 복사하는 방식이 되지 않도록 코드 스크린샷 형식을 유지한다. 상세 기준은 [코드 스크린샷](#code-screenshots)을 따른다.

## 2. 공통 실습 범위

현재 [OT 원본](../weekly-slides/weekly-slides/LAB0_OT_0907/03.LAB0_OT_0907.tex)의 LAB1 목록을 기준으로 한다. 과거 구성안의 6개 실습으로 축소하지 않는다.

각 회로에 다음 내용을 갖춘다.

1. 입출력, 비트 폭, 진리표 또는 연산 규칙, 예상 결과.
2. 설계 소스와 top 모듈, 테스트벤치, 파일별 역할.
3. Vivado 실행 전에 VS Code에서 테스트벤치를 실행하는 방법, 실제 로그·파형, 예상값과의 비교 및 실험 전 레포트 작성 항목.
4. 같은 설계와 테스트 조건으로 Vivado에서 다시 시뮬레이션하는 방법과 VS Code 결과와의 비교.
5. 대상 FPGA와 핀 제약, 합성·배치배선·비트스트림 생성, 실제 기기에 비트스트림을 쓰는 절차와 성공 확인 방법.
6. 보드 입력·출력의 실제 동작 확인, 사진·영상 촬영, GitHub 업로드 및 실험 후 레포트에서 결과를 설명하고 링크하는 방법.

입력 경우의 수가 작은 회로는 전 조합을 검사하고 그 외에는 정상·경계 조건을 포함한다. carry/borrow, MUX 비트 순서, 인코더의 다중 입력 처리, 7세그먼트의 비트 순서와 점등 극성을 명시한다. 개별 실습은 조합회로에 집중한다. 통합 프로젝트에 필요한 모드 레지스터·버튼 처리·LCD 제어·표시 장치 스캔은 제공용 공통 보드 제어 코드로 분리한다.

### 22개 프로젝트 공통: VS Code 입문부터 시작

- **22개 모두 매뉴얼 맨 앞에서 VS Code를 새 창으로 열어 사전 시뮬레이션부터 한다.** 레거시 10개·최신 10개·최신 통합 1개는 파형 분석과 실험 전 레포트 작성 뒤 Vivado GUI를 연다. 오픈소스 통합 1개도 같은 사전 단계를 마친 뒤 CLI 빌드로 진행한다.
- VS Code를 모르는 학생을 전제로 **레거시 교안만큼 버튼 하나하나 친절하게** 설명한다. `File → New Window`, `File → Open Workspace from File...`, 선택할 workspace, Explorer의 폴더 펼치기, 파일 탭, 저장, 확장 확인, 작업 메뉴, 실행 결과, 파형 신호 추가·확대·커서 읽기를 실제 화면과 함께 안내한다. 단축키는 메뉴 설명의 보조로 둔다.
- 단계마다 클릭 위치·입력할 값·화면에서 확인할 결과·실패했을 때 돌아갈 단계가 있어야 한다. “시뮬레이션한다” 한 줄이나 설치 매뉴얼 링크만으로 대체하지 않는다. 앞부분의 실습 목차에서 VS Code와 Vivado 단계로 각각 이동할 수 있게 한다.
- 실제 배포 workspace·RTL·테스트벤치·작업을 열어 사용자의 **VS Code 화면**을 캡처한다. 이 사전 단계는 레거시 01 앞에 추가하더라도 새 안내이므로 실제 편집기 캡처 기준을 적용한다. 뒤에 이어지는 레거시 원문 캡처는 그대로 보존한다.
- VS Code가 편집기라는 점과 실제 시뮬레이터를 명확히 구분한다. XSim을 쓰는 경우 “Vivado GUI를 열기 전”이라는 뜻이며 Vivado 시뮬레이션 도구의 사전 설치는 필요하다고 안내한다. 경로·버전·파형 뷰어·실제 검사 완료 로그를 기록한다.
- 시뮬레이션 성공 로그뿐 아니라 입력 자극·기대 출력·실제 파형을 비교하고 실험 전 레포트에 넣을 캡처와 해석을 구체적으로 안내한다. 저장 후 재실행·파형 갱신, 잘못된 workspace, 도구 경로 누락, VCD가 텍스트로 열리는 경우도 다룬다.
- **기준 예제는 `04.LAB1_11_LOGIC_GATES_LEGACY.tex`다.** 기존 VS Code 안내를 피드백에 맞춰 보완한 뒤 나머지 21개에 확장한다. 01번 사전 시뮬레이션의 완료를 22개 프로젝트 전체나 실제 보드 검증의 완료로 기록하지 않는다.

### 소스코드 스크린샷 기준

- 레거시 슬라이드는 원본 교안의 사진·문구·코드 이미지를 유지한다. 새 편집기 스타일로 다시 그리거나 대체하지 않는다.
- 그 외 VS Code 사전 시뮬레이션, Vivado 2026.1, 두 통합 프로젝트, CLI 매뉴얼의 소스코드는 **사용자가 현재 설정해 둔 편집기 테마의 VS Code**에서 실제 배포 파일을 열어 캡처한다. 테마 이름만 비슷한 임의 색상이나 별도 코드 이미지 생성기로 대체하지 않는다.
- RTL·테스트벤치·스크립트 등 슬라이드에서 설명하는 코드 블록은 스크린샷으로 삽입한다. 같은 코드를 `listings`·`minted`·일반 텍스트로 중복 수록하거나 이미지 위에 선택 가능한 코드 텍스트를 겹치지 않는다.
- 실제 편집기의 구문 강조·들여쓰기·줄 번호를 유지하고, 코드와 파일 식별에 필요한 부분을 중심으로 캡처한다. 발표 화면에서 읽히는 글자 크기를 확보하고, 긴 코드는 의미 단위로 여러 장에 나눈다.
- 배포 소스의 최종 내용과 캡처가 일치하는지 확인한다. 슬라이드에는 파일명·설명 대상 줄·핵심 동작을 텍스트로 적고 해당 프로젝트 및 원본 소스를 링크한다.
- 캡처는 PNG 등 선명한 로컬 이미지로 저장하여 TeX에서 상대경로로 불러온다. 새 PNG는 Git에 추가하지 않고 렌더링된 PDF를 커밋한다. PDF를 다시 만들 때도 코드가 이미지인 상태를 유지하며 코드 OCR 텍스트층을 추가하지 않는다.
- 학생이 직접 실행할 짧은 터미널 명령·경로·파일명은 사용성을 위해 텍스트로 안내할 수 있다. 회로 소스코드를 텍스트로 길게 나열하는 방식은 사용하지 않는다.
- 목적은 슬라이드에서 무심코 코드를 바로 복사하는 것을 줄이고 구조를 읽고 이해하도록 하는 것이다. **저장소에서 해당 소스를 직접 찾아 가져올 수 있는 학생은 복사해서 사용해도 된다.** 실행 가능한 소스 파일과 링크는 계속 제공한다. 이미지 형식은 슬라이드의 즉석 복붙을 줄이기 위한 선택이며, 학습 확인은 파형 해석·코드 설명·실제 동작 검증으로 한다.

## 3. A — Vivado 2026.1 매뉴얼

**대상:** Vivado를 처음 사용하는 학부 2학년 수준의 초심자.

- **실제 Vivado 2026.1에서 직접 실습하고 스크린샷을 찍어** 새로 작성한다.
- Vivado의 프로젝트·파형·구현 화면은 실제 Vivado에서 캡처하고, 설계 코드·테스트벤치 설명용 이미지는 [VS Code 캡처 기준](#code-screenshots)을 따른다.
- 개별 프로젝트 10개와 [통합 프로젝트](#integrated) 1개, 전용 workspace 11개를 제공한다. 개별 실습에서 통합 프로젝트의 해당 모드로 이동하는 링크를 둔다.
- 레거시와 같은 수준으로 자세히 설명한다. 클릭할 메뉴·버튼, 입력값, 단계의 목적, 다음 단계로 넘어가는 기준을 함께 제시한다.
- VS Code에서 소스·테스트벤치 작성 → 사전 시뮬레이션·파형 해석 → 실험 전 레포트 → Vivado 프로젝트 생성·부품 선택·소스 등록 → Vivado 시뮬레이션·결과 비교 → 핀 제약 → 합성 → 구현 → 비트스트림 생성 → 실제 FPGA 기록 → 동작 확인·사진·영상 → GitHub 업로드·실험 후 레포트 순서로 구성한다.
- 첫 회로에서 공통 절차를 충분히 설명하고, 이후에는 참조할 공통 절차와 변경할 소스·top·핀·검증 항목을 정확히 안내한다.
- VS Code 실행 로그·파형, Vivado 프로젝트 설정·소스와 top·파형·핀 설정·합성·구현 결과·비트스트림 생성 및 기록 완료 화면, 실제 보드 동작 사진·영상을 확보한다.
- 기존 설치 및 [VS Code 환경설정 매뉴얼](../weekly-slides/weekly-slides/LAB1_FPGA_0914/02.vscode_verilog_환경설정_매뉴얼.tex)을 연결한다. 설치 설명은 참조하되 회로별 사전 시뮬레이션·파형 해석·레포트 작성 과정은 이번 매뉴얼에 반드시 포함한다.

**완료 기준:** 개별 프로젝트 10개와 통합 프로젝트 1개의 VS Code·Vivado 시뮬레이션, 비트스트림 생성, 실제 FPGA 기록·동작 확인을 수행하고 설명·증빙·배포 코드가 일치한다. 통합본은 10개 모드와 버튼·LCD 제어까지 검증한다. 사진·영상과 GitHub 링크를 갖춘 실험 전·후 레포트 예시를 제공한다. 장비 연결·촬영을 수행하지 못했다면 해당 항목은 미완료로 남기며 비트스트림 생성만으로 전체 실험 완료를 선언하지 않는다.

## 4. B — macOS ARM64용 오픈소스 CLI 매뉴얼

**대상:** 개발 경험이 있고 터미널을 사용할 수 있는 Apple Silicon Mac 사용자. 두 Vivado 매뉴얼보다 훨씬 간단하고 명료하게 작성한다.

### 실행 환경과 검증 범위

- 제작자에게 Mac이 없다는 전제로 진행한다. 실제 Mac 확보나 macOS 실행 검증을 완료 조건으로 요구하지 않는다.
- **macOS ARM64 바이너리가 배포되는 오픈소스 도구를 선정하고, 제작 PC의 WSL Ubuntu-26.04에서 해당 도구의 Linux 바이너리로 동일한 CLI 흐름을 실행한다.**
- 플랫폼별 설치 파일을 구분하고 회로 처리 명령과 입력 파일은 가능한 한 공통으로 사용한다. macOS 바이너리를 WSL에서 실행하는 방식이 아니다.
- 공식 배포처에서 macOS ARM64 바이너리 존재를 확인하고 릴리스·링크·필수 구성 요소를 기록한다. Linux 쪽도 가능한 한 같은 릴리스로 맞춘다.
- 검증 범위를 “macOS ARM64 배포 확인 / WSL에서 명령 실행 및 비트스트림 생성 확인”으로 명시한다.

### 도구 선정과 실제 실행

1. OSS CAD Suite를 우선 후보로 검토한다. 공식 안내에 `darwin-arm64` 배포가 있으며 WSL에는 호스트 아키텍처에 맞는 Linux 배포를 사용한다.
2. 합성기뿐 아니라 **대상 부품의 배치배선 도구·디바이스 데이터베이스·비트스트림 생성기까지** 필요한 구성 요소와 macOS ARM64 사용 가능 여부를 확인한다. ARM64 배포가 있다는 사실만으로 `xc7s75fgga484-1` 전체 흐름이 지원된다고 판단하지 않는다.
3. 먼저 논리 게이트 예제 하나로 설치 → 환경 설정 → 시뮬레이션 → 합성 → 배치배선 → 비트스트림 생성까지 실제 명령을 실행한다.
4. 성공한 흐름으로 10개 회로와 버튼·LCD 제어를 포함한 **통합 프로젝트 1개**를 빌드한다. Vivado 통합본과 같은 RTL·동작 명세·보드 핀 정의를 사용하고 도구별 빌드 설정과 제약 표현만 분리한다. 대표 회로 실험은 지원 확인 단계이며 별도 배포 프로젝트 수에 포함하지 않는다.
5. 도구나 부품 지원 문제로 막히면 실패 단계·명령·원인·필요한 구성 요소를 기록하고 가능한 다른 오픈소스 흐름을 조사한다. 다른 FPGA의 성공을 대상 보드의 성공으로 대체하지 않는다.

### 학생에게 제공할 내용

- 도구·버전, macOS ARM64 설치 파일 링크, 설치·환경 설정 명령.
- 복사하여 실행할 수 있는 명령 또는 스크립트와 정확한 작업 디렉터리·입력 파일.
- 배포 스크립트는 원본 파일로 제공하되 슬라이드에서 그 내용을 설명하는 코드 블록은 VS Code 스크린샷으로 보여준다. 짧은 실행 명령은 텍스트로 제공한다.
- 시뮬레이션 → 합성 → 배치배선 → 비트스트림 생성의 짧은 설명과 성공 확인 방법.
- 통합 top·제약 파일·최종 비트스트림 경로와 모드 01~10의 입력·출력 대응표. 회로별 테스트 실행 방법도 제공한다.
- macOS와 WSL에서 달라지는 설치·경로 설정. 문법 입문이나 GUI 클릭 설명은 반복하지 않는다.

**완료 기준:** 필수 도구의 macOS ARM64 배포를 확인하고 WSL에서 **10개 모드와 버튼·LCD 제어를 포함한 통합 비트스트림 1개**를 실제로 생성한다. 개별 회로와 통합 동작을 VS Code에서 실행할 수 있는 테스트로 확인하고 Vivado 통합본과 예상 결과를 대조한다. 명령은 검증한 값으로 작성한다. 대상 부품 지원 문제로 끝까지 실행하지 못한 경우에는 가능한 범위와 남은 문제를 명시하고 완료로 표시하지 않는다. Mac 실기 검증과 Mac에서의 보드 프로그래밍은 이 대안 경로 자체의 필수 완료 조건이 아니다. 다만 수업의 실험 후 레포트에는 실험실 Vivado 환경에서의 시뮬레이션·실제 보드 기록·사진·영상이 필요하며, CLI 비트스트림 생성 결과로 이를 대신하지 않는다.

공식 배포 참고: [OSS CAD Suite 안내](https://github.com/YosysHQ/oss-cad-suite-build), [릴리스](https://github.com/YosysHQ/oss-cad-suite-build/releases).

## 5. C — 레거시 Vivado 매뉴얼

**대상:** 구버전 Vivado를 사용하는 학부 2학년 수준의 초심자.

- [레거시 자료](../legacy/)에서 해당 원본 교안을 찾아 사용 버전·장비·원본 파일·페이지를 정리한다.
- 회로별로 독립적으로 열 수 있는 Vivado 프로젝트 10개를 제공하고, 각 매뉴얼에서 해당 README·workspace·`.xpr`로 연결한다. 원본에 맞는 Vivado 버전을 기록하고 최신 버전에서 저장한 프로젝트를 구버전 호환 검증 없이 레거시용으로 배포하지 않는다.
- 레거시 절차에 들어가기 전에 VS Code 새 창 열기부터 사전 시뮬레이션·파형 해석·실험 전 레포트 단계를 해당 매뉴얼 앞부분에 수록한다. 설치 매뉴얼은 보조 링크로 제공하고 원본에 없는 사전 안내임을 구분한다.
- **원본 사진과 문구를 그대로** TeX 슬라이드로 재구성한다. 임의로 요약하거나 최신 화면으로 바꾸지 않는다.
- 프로젝트 생성, 부품 선택, 소스 등록, top 지정, 시뮬레이션, 제약 입력, 합성·구현, 비트스트림 생성, 원본의 보드 다운로드 절차를 빠짐없이 옮긴다.
- 원본 오류나 현재 환경과 다른 조건은 원문과 분리한 주석으로 설명한다. 원본에 없는 보충 설명은 보충임을 표시한다.
- 기존 `00.legacy_hdl.tex`와 PDF는 재사용할 내용을 확인하는 참고 자료로 삼고 원본 교안과 대조한다.

**완료 기준:** 10개 회로의 원문·사진 대응과 프로젝트·workspace 10개를 확인하고, 초심자가 VS Code 사전 시뮬레이션부터 Vivado·보드 실험·레포트까지 따라갈 수 있다. 프로젝트별로 VS Code 시뮬레이션, 지정한 구버전에서 열기·시뮬레이션·비트스트림 생성, 실제 보드 기록·동작 확인의 검증 여부를 기록한다. 해당 버전이나 장비를 실행하지 못했다면 해당 단계는 미검증으로 표시한다.

- 프로젝트별로 VS Code 시뮬레이션과 Vivado 시뮬레이션의 로그·파형 출력 경로를 분리한다. 같은 입력 자극·예상값을 사용하고 도구별 테스트벤치 차이가 필요하면 이유와 대응 관계를 기록한다.
- Vivado 프로젝트 21개에는 `.xpr`와 재생성용 Tcl을 제공한다. CLI 통합 프로젝트에는 검증된 빌드 스크립트를 제공한다. 각각 README에 GUI로 열기 또는 CLI 실행 방법을 명시한다.
- 공통 RTL을 참조하여 수정이 두 통합본에 반영되게 한다. 레거시 원문·버전 호환 때문에 필요한 차이만 별도로 유지하고 이유를 기록한다.
- 빌드 산출물은 프로젝트별 경로로 분리하여 서로 덮어쓰지 않게 한다. 캐시·임시 파일을 소스와 분리하고 배포 비트스트림의 위치는 README와 검증표에 명시한다.

## 7. 통합 프로젝트의 동작 명세

Vivado 통합본과 CLI 통합본은 같은 소스와 동작을 제공한다.

1. 비트스트림 하나에 조합회로 10개를 포함한다. 모드 변경은 입출력 선택으로 구현하고 FPGA를 다시 프로그래밍하지 않는다.
2. 모드 버튼을 누를 때마다 교육 번호 순서로 `01 → 02 → … → 10 → 01`을 순환한다. 리셋하면 모드 01로 복귀한다.
3. LCD에 현재 모드 번호와 회로 이름을 표시한다. 실제 LCD의 행·열 수와 지원 문자를 확인하여 짧은 표시 문자열을 정하고, 공간이 남으면 입력·출력을 표시한다.
4. 스위치·버튼을 선택한 회로의 입력에 연결하고 결과를 LED·7세그먼트 등에 표시한다. 모드 선택 버튼과 데이터 입력을 구분하고 사용하지 않는 출력의 상태도 정의한다.
5. 모드별 입력 폭·스위치 배치·출력 위치·LCD 문자열·예상 결과를 하나의 대응표로 작성한다. 보드 입력 수가 부족하면 입력 뱅크 선택 등 실제 조작 방식을 명시하고 두 통합본에 동일하게 적용한다.
6. 버튼 동기화·디바운싱·단발 펄스 검출을 구현한다. 길게 누르거나 바운스가 발생해도 한 번 누름에 한 모드만 이동하도록 한다.
7. 실제 보드 문서에서 클록·리셋·LCD 인터페이스·타이밍·핀·전기 규격을 확인하여 제어기를 작성한다. 공통 보드 제어 코드는 조합회로 실습 코드와 구분하고 역할을 설명한다.
8. 테스트벤치에서 리셋, 10개 모드 순환과 되돌아감, 버튼 바운스·길게 누름, 회로별 입력·출력, LCD 초기화·표시 갱신을 검증한다. 실제 보드 확인 여부는 별도로 기록한다.

## 9. VS Code 사전 시뮬레이션과 실험 전·후 레포트

### 필수 진행 순서

**회로 이해·설계 → VS Code에서 시뮬레이터 실행·파형 분석 → 실험 전 레포트 → Vivado 시뮬레이션·비교 → 합성·구현·비트스트림 생성 → 실제 FPGA에 기록·동작 확인 → 사진·영상·자료의 GitHub 업로드 → 실험 후 레포트에 결과와 링크 정리.**

22개는 제공할 프로젝트의 수다. 학생이 같은 회로를 도구 버전마다 중복하여 22번 제출한다는 의미는 아니다. 선택한 실습 환경과 프로젝트를 명시하고 회로 10개의 결과를 추적할 수 있게 한다. 별도의 배점·기한·제출 횟수는 이 문서에서 임의로 추가하지 않는다.

### 실험 전 레포트 — VS Code 시뮬레이션까지 자세히

1. 회로의 목적·동작 원리·입출력·진리표 또는 연산 규칙과 예상 결과를 설명한다.
2. 설계 코드의 구조, 핵심 구문, 모듈 연결, 비트 폭과 top을 설명하고 소스 파일을 링크한다.
3. 테스트벤치의 입력 자극·정상 및 경계 조건·기대값·자동 검사 방법·종료 조건을 설명한다.
4. VS Code workspace, 실제 시뮬레이터·버전, 실행 task 또는 명령, 작업 디렉터리, 파형 생성·열기 과정을 재현 가능하게 기록한다.
5. 실행 로그와 파형 원본·캡처를 남기고, 시간 구간별 입력과 출력이 왜 그렇게 나오는지 예상값과 비교하여 자세히 해석한다. 캡처만 붙이고 설명을 생략하지 않는다.
6. 발견한 오류, 원인, 수정 내용과 재실행 결과를 기록한다. 실험에서 확인할 보드 입력·출력과 예상 동작도 정리한다.
7. 회로별 소스·테스트벤치·로그·파형과 레포트를 연결한다. 사전 검증에 사용한 코드 버전 또는 커밋을 기록하여 이후 수정과 비교할 수 있게 한다.

### 실험 후 레포트 — Vivado부터 실제 장비·GitHub 증빙까지

1. 사용한 프로젝트·Vivado 버전·대상 부품·top·제약 파일을 기록한다.
2. Vivado에서 같은 설계를 시뮬레이션하고 파형·로그를 제시한다. VS Code 사전 결과와 비교하여 일치 여부와 차이의 원인을 설명한다.
3. 합성·구현 결과와 필요한 경고·수정 사항을 정리하고 생성한 비트스트림의 파일 경로와 코드 버전을 기록한다.
4. 보드 연결, 대상 장치 확인, 비트스트림 선택·기록 및 완료 확인 절차를 기록한다. 생성 성공 화면과 실제 장치에 쓴 결과를 각각 확보한다.
5. 실제 입력을 조작하여 출력이 바뀌는지 확인하고 예상값·두 시뮬레이션·실측 동작을 비교한다. 문제 발생 시 원인·수정·재검증 과정을 설명한다.
6. 보드 연결 상태와 입출력을 알아볼 수 있는 사진, 입력 조작에 따른 출력 변화를 확인할 수 있는 시연 영상을 촬영한다. 통합본 영상에는 모드 순환과 LCD의 모드 표시, 해당 회로의 동작이 드러나게 한다. 회로 10개를 개별 증빙 또는 통합 영상의 타임스탬프로 추적할 수 있게 한다.

8. 최종 결과·한계·고찰을 작성하고, 사용한 코드 커밋과 증빙의 대응 관계를 남긴다. 실제로 수행하지 못한 보드 기록·동작·촬영은 미완료로 기록한다.

### 12.3 레거시와 최신 코드
