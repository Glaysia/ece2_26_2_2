\begin{frame}{도구의 역할}\relax
\small
\begin{enumerate}\setlength{\itemsep}{0.22cm}
\item VS Code: 파일 편집과 작업 실행.
\item Git: 템플릿을 받고 자신의 변경을 기록.
\item Python 3.10 이상: tools/lab1.py 실행.
\item Icarus Verilog: iverilog로 컴파일, vvp로 시뮬레이션.
\item slang: 편집 중 진단. VaporView: 생성된 VCD 파형 표시.
\item Vivado: 이후 같은 소스로 시뮬레이션·합성·구현. CLI 과정은 해당 도구를 사용한다.
\end{enumerate}

\end{frame}

\begin{frame}[label=vscode-install-tools]{Windows · VS Code와 Git}\relax
\small
\begin{enumerate}\setlength{\itemsep}{0.22cm}
\item 아래 공식 VS Code 설치 안내에서 Windows User Setup을 받는다.
\item 설치 화면의 PATH 추가 항목을 확인하고 설치를 마친다.
\item Git for Windows도 설치하고 명령줄에서 Git을 사용할 수 있게 한다.
\item 설치 후 기존 VS Code와 터미널을 닫고 새로 연다.
\end{enumerate}
\href{https://code.visualstudio.com/docs/setup/windows}{VS Code 공식 설치}\quad\href{https://git-scm.com/install/windows}{Git 공식 설치}
\end{frame}

\begin{frame}{Windows · Python 설치}\relax
\small
\begin{enumerate}\setlength{\itemsep}{0.22cm}
\item Python 공식 Windows 설치 프로그램을 실행한다.
\item Add python.exe to PATH를 선택하고 Install Now를 누른다.
\item 설치 후 VS Code와 PowerShell을 다시 연다.
\item 아래 명령이 실제 Python 버전을 출력하는지 확인한다.
\end{enumerate}
\terminalbox{python --version}
제작 PC에서는 Python 3.12.10으로 실습했다. 3.10 이상이 필요하다.\par\href{https://docs.python.org/3.12/using/windows.html}{Python 공식 Windows 설치 안내}
\end{frame}

\begin{frame}{Windows · Icarus 설치}\relax
\small
\begin{enumerate}\setlength{\itemsep}{0.22cm}
\item MSYS2 공식 설치 안내에 따라 설치·초기 업데이트를 마친다.
\item 시작 메뉴의 MSYS2 MINGW64 터미널을 연다.
\item 아래 명령을 입력하고 패키지 설치를 완료한다.
\end{enumerate}
\terminalbox{pacman -S mingw-w64-x86\_64-iverilog}
기본 설치 경로는 C:/msys64/mingw64/bin이다. iverilog.exe와 vvp.exe를 함께 제공한다.\par\href{https://www.msys2.org/}{MSYS2 설치}\quad\href{https://packages.msys2.org/packages/mingw-w64-x86_64-iverilog}{Icarus 패키지·설치 명령}
\end{frame}

\begin{frame}{Windows · Icarus를 PATH에 추가}\relax
\small
\begin{enumerate}\setlength{\itemsep}{0.22cm}
\item 시작 메뉴에서 계정의 환경 변수 편집을 검색해 연다.
\item 사용자 변수의 Path 선택 → 편집 → 새로 만들기.
\item C:/msys64/mingw64/bin을 추가하고 열린 창의 확인을 누른다.
\item 설치 위치를 바꿨다면 자신의 mingw64/bin 경로를 넣는다.
\item VS Code를 모든 창까지 종료하고 다시 연다.
\item Terminal → New Terminal에서 다음 장의 버전을 확인한다.
\end{enumerate}

\end{frame}

\begin{frame}{Windows PowerShell · 버전 확인}\relax

\terminalbox{git --version\\python --version\\iverilog -V\\vvp -V\\Get-Command python, iverilog, vvp}
이름을 찾을 수 없으면 설치 위치와 PATH를 확인한다.\par\vspace{0.22cm}Python 대신 Store가 열리거나 버전이 없으면 실제 Python 설치와 호출 경로를 확인한다.\par
\end{frame}

\begin{frame}[label=vscode-install-clone]{v2.0.0 템플릿을 새 이름으로 받기}\relax

\begin{frame}{LAB1.code-workspace 열기}\relax
\small
\begin{enumerate}\setlength{\itemsep}{0.22cm}
\item 방금 clone한 폴더로 이동한다.
\item LAB1.code-workspace를 선택하고 Open을 누른다.
\item Explorer의 PROJECT 아래에 src·sim·constraints·tools가 보이는지 확인한다.
\item RTL·TB·XDC는 주석뿐인 시작 파일이다. 회로 PDF를 보며 작성한다.
\item Restricted Mode라면 출처와 실행할 작업을 읽고 해당 프로젝트의 신뢰 여부를 직접 결정한다.
\end{enumerate}

\end{frame}

\begin{frame}{추천 확장 세 개 설치}\relax
\small
\begin{enumerate}\setlength{\itemsep}{0.22cm}
\item 왼쪽 Extensions 아이콘 클릭 → 검색창에 @recommended 입력.
\item slang → Install: Verilog/SystemVerilog 편집 진단.
\item VaporView → Install: VCD 파형 보기.
\item vscode-pdf → Install: PDF 교안을 편집기 옆에서 보기.
\item 이미 설치되어도 Disabled 상태이면 해당 확장의 Enable (Workspace)을 선택한다.
\end{enumerate}
확장 설치와 Python·Icarus 설치는 각각 필요하다.\par
\end{frame}

\begin{frame}{빈 파일을 내 회로 파일로 바꾸기}\relax
\small
\begin{enumerate}\setlength{\itemsep}{0.22cm}
\item Explorer에서 src/design.v 우클릭 → Rename. 회로 PDF의 RTL 파일명으로 변경한다.
\item sim/tb\_design.v와 constraints/pins.xdc도 같은 방법으로 변경한다.
\item 각 파일을 두 번 눌러 열고 전체 코드 이미지를 보며 직접 입력한다.
\item RTL이 여러 개라면 src 우클릭 → New File로 각각 만든다.
\item File → Save All. 파일명과 module 이름을 구분한다.
\end{enumerate}

\end{frame}

\begin{frame}{simulation.json 수정}\relax
\small
\begin{enumerate}\setlength{\itemsep}{0.22cm}
\item Explorer에서 simulation.json을 두 번 누른다.
\item sources 배열에 자신이 만든 src/... 파일들을 모두 등록한다.
\item testbench에는 sim/... 파일 경로를 적는다.
\item simulation\_top에는 테스트벤치 module 이름을 적는다.
\item 경로의 큰따옴표·쉼표·대괄호를 확인하고 Save All.
\end{enumerate}
\href{04.LAB1_01_LOGIC_GATES_VIVADO.pdf}{첫 회로의 전체 JSON·RTL·TB·XDC 화면}
\end{frame}

\begin{frame}[label=vscode-install-sim]{세 작업을 순서대로 실행}\relax
\small
Terminal → Run Task...을 누른다. 메뉴가 숨겨졌으면 상단 …을 확인한다.\par\par\vspace{0.18cm}{\centering\includegraphics[width=\textwidth,height=2.1cm,keepaspectratio,trim=219.75bp 507.75bp 219.75bp 0bp,clip]{assets/modern-01/06-tasks.png}\par}\vspace{0.16cm}
\begin{enumerate}\setlength{\itemsep}{0.22cm}
\item 01 Check tools: Python·Icarus 실행을 확인한다.
\item 02 Simulate: 작성한 RTL·TB를 컴파일하고 실행한다.
\item 03 Open waveform: 생성된 wave.vcd를 연다.
\end{enumerate}
Vivado 실행은 이 세 작업에 포함되지 않는다. 해당 실습의 Vivado GUI 절차를 뒤에서 진행한다.\par
\end{frame}

\begin{frame}{PASS·검사 수·시간 읽기}\relax
\small
SIMULATED는 실행기의 완료 상태다. TB의 LAB1\_PASS와 검사 수까지 확인한다.\par\vspace{0.22cm}첫 논리 게이트는 4개 검사, 40ns 종료다. 회로마다 검사 수·종료 시각은 다르므로 자신의 PDF와 대조한다.\par\vspace{0.22cm}build/sim/result.json과 실행별 simulation.log, wave.vcd를 보관한다.\par\vspace{0.22cm}실패 시 FAIL 문구의 입력·예상값·실제값을 읽고 코드 수정 → Save All → 02 Simulate로 다시 실행한다.\par
\end{frame}

\begin{frame}{VaporView 파형 열기}\relax
\small
\begin{enumerate}\setlength{\itemsep}{0.22cm}
\item 03 Open waveform을 실행한다.
\item 텍스트로 열리면 VCD 탭 우클릭 → Reopen Editor With... → VaporView.
\item Netlist에서 테스트벤치를 펼치고 입력·출력 신호를 추가한다.
\item Zoom to Fit으로 전체 시간을 본다.
\item 구간 중간에 커서를 두고 입력과 출력 값을 진리표와 비교한다.
\item 파형이 비어 있으면 신호 추가 여부와 이번 실행의 VCD인지 확인한다.
\end{enumerate}

\end{frame}

\begin{frame}{실행이 안 될 때 확인할 순서}\relax
\small
\begin{enumerate}\setlength{\itemsep}{0.22cm}
\item 작업 메뉴가 없다: 올바른 LAB1.code-workspace를 열었는지 확인.
\item Python·iverilog를 못 찾는다: Get-Command 결과, PATH, VS Code 재시작 확인.
\item 컴파일 실패: 로그의 첫 오류, 파일명·세미콜론·괄호 확인.
\item top을 찾지 못한다: simulation\_top과 TB module 선언 비교.
\item FAIL 또는 timeout: 입력·기대값·종료 조건과 watchdog 확인.
\item 파형 편집기가 없다: VaporView 설치·Enable (Workspace) 확인.
\end{enumerate}

\end{frame}
