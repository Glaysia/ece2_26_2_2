# LAB1 — FPGA·Verilog 입문과 조합회로

- 수업: 2026년 9월 14일 월요일, 14:00~18:00
- 대상: Verilog와 개발 도구를 기초부터 익히는 수강생
- 구성: 기본 실습 6개 + 공개 통합 실습 + 당일 응용과제
- 핵심: 조건에 따라 출력이 달라지는 조합회로를 설계하고 시뮬레이션·FPGA에서 검증한다.

## 1. 문서의 역할

이 문서는 LAB1의 학습 범위, 실습 요구사항, 검증 기준, 진행 방식에 대한 단일 기준 문서(SSOT)다. LAB1 슬라이드·예제·실습 안내는 이 문서를 기준으로 작성하고, 내용 변경 시 이 문서를 먼저 수정한다.

- 공통 제출·평가 정책은 저장소 루트의 `0906_보고서_채점_조건.md`를 따른다. LAB1에 별도 배점이나 제출 기한을 임의로 만들지 않는다.
- 당일 응용과제의 문제·정답·비공개 검사용 데이터는 사전 공개 문서에 포함하지 않는다.
- 아래 실습 명세는 제작 기준이다. 해당 코드·XDC·실행 설정이 모두 제작 및 보드 검증되었다는 뜻은 아니다.

## 2. LAB1의 도달 목표

수업 종료 시 다음을 할 수 있어야 한다.

1. 요구사항을 입력·출력·진리표로 표현한다.
2. 비트와 벡터, 상수, 비트 연산으로 조합회로를 기술한다.
3. `assign`과 조합 `always`의 용도를 이해하고 `if/case`로 조건을 표현한다.
4. 가산기·감산기·비교기·MUX·인코더·디코더의 역할을 설명한다.
5. 작은 모듈을 연결하여 하나의 조합회로 시스템을 구성한다.
6. 테스트벤치로 정상·경계 입력을 검사하고 파형과 실제 출력의 차이를 분석한다.

분기와 반복을 컴퓨터 동작의 출발점으로 보되, LAB1은 그중 연산·조건 판단·선택에 집중한다. 기억과 시간에 따른 반복은 LAB2의 레지스터·카운터·FSM으로 연결한다.

## 3. 범위와 압축 원칙

레거시의 HDL 입문·모델링·조합논리 약 3주 분량을 기능 중심으로 재구성한다. 모든 회로 변형을 반복 구현하는 대신 대표 회로를 빠르게 만들고 통합한다.

| 반드시 다룰 내용 | 처리 방식 |
|---|---|
| module, 입출력, 내부 신호, 인스턴스 | 작은 실행 예제에서 바로 설명 |
| wire/reg, 비트 폭, 이진·십진·16진 상수 | 실제 코드와 파형 표시에 연결 |
| 비트 연산과 논리 연산 | `&`와 `&&`처럼 결과가 달라지는 사례 비교 |
| assign, always @*, if/case | 조합회로의 출력이 모든 경우에 정해지도록 작성 |
| 가산·감산·비교·선택·부호화·복호화 | 기본 실습 6개에서 대표 예제 구현 |
| 테스트벤치·파형·FPGA 구현 | 공통 프로젝트를 재사용하여 반복 |

줄이거나 제외할 내용:

- TTL 부품 종류 암기, FPGA 역사, 구형 ISE·Schematic 실습
- 게이트마다 프로젝트를 새로 만드는 절차
- 같은 회로를 세 가지 모델링 방식으로 모두 제출하는 과제
- 카르노맵 풀이의 반복, 게이트 피드백으로 DFF 만들기
- 클록 분주·레지스터·카운터·FSM·동적 FND 스캔 구현: LAB2 이후로 이관

`reg` 선언만으로 플립플롭이 생기는 것은 아니다. 조합 블록은 기본값과 모든 분기를 지정하여 의도하지 않은 래치를 방지한다. 회로 기술의 `for`를 클록에 따른 반복으로 설명하지 않는다.

- 테스트벤치에는 시간 단위, 초기 입력, 유한한 검사 구간과 종료 조건을 둔다.
- 조합회로라도 테스트벤치에서는 입력 변경 후 출력이 반영될 시간을 두고 검사한다.

## 5. 기본 실습 6개

### 실습 1 — 게이트와 비트 연산

- 제공된 AND 예제를 실행한 뒤 OR·XOR·NOT으로 확장한다.
- 1비트 진리표에서 4비트 벡터 연산으로 확장한다.
- `&`와 `&&`, `~`와 `!`의 차이를 실제 결과로 확인한다.
- 검증: 2입력 게이트의 네 경우를 모두 확인하고, 벡터 입력 `0011`, `0101`의 결과를 예상·비교한다.

### 실습 2 — 반가산기와 전가산기

- 반가산기의 합·자리올림을 구현한다.
- 반가산기 두 개와 OR 연산을 연결하여 전가산기를 구성한다.
- 포트는 이름으로 연결하고 외부 포트와 내부 연결 신호를 구분한다.
- 검증: 반가산기 4가지, 전가산기 8가지 입력을 모두 검사한다.

### 실습 3 — 4비트 가산기·감산기

- `a[3:0]`, `b[3:0]`의 덧셈과 뺄셈을 구현한다.
- 덧셈은 입력을 5비트로 확장하여 carry를 보존한다.
- 뺄셈 결과는 하위 4비트로 표현하고 borrow는 `a < b`로 별도 표시한다.
- 검증: `0+0`, `15+1`, `15+15`, `0-1`, `15-15`, `3-5`를 포함한다.
- 기본 입력은 unsigned다. 음수의 signed 해석은 비교 설명으로 구분한다.

### 실습 4 — 비교기와 MUX

- 두 4비트 입력의 `a>b`, `a==b`, `a<b`를 구현한다.
- 선택 신호로 여러 결과 중 하나를 출력하는 MUX를 만든다.
- 조합 `always @*`, blocking 할당(`=`), `if/case`와 기본값을 다룬다.
- 검증: 대소·동일 조건, 모든 선택값, 입력과 선택 신호 변경을 확인한다.

### 실습 5 — 인코더·디코더·7세그먼트

- 4입력 우선순위 인코더를 만든다. 높은 비트 우선, 무입력은 `valid=0`, 코드 0으로 정한다.
- 2비트 코드를 4비트 one-hot 출력으로 바꾸는 디코더를 만든다.
- 4비트 값을 한 자리 16진수 `0~F`의 세그먼트 패턴으로 변환한다.
- 검증: 인코더 16가지 입력, 디코더 4가지 입력, 표시값 16가지를 확인한다.
- 세그먼트 순서·극성은 배포 보드에 맞게 명시한다. 여러 자리의 동적 스캔은 구현하지 않는다.

### 실습 6 — 모듈 연결과 표시

- 연산기, 선택 회로, 표시 디코더를 top에서 연결한다.
- 모듈별 테스트와 연결 후 테스트를 구분한다.
- 검증: 포트 순서·폭·누락, 출력 극성, top 및 XDC 포트 이름을 확인한다.
- 실습 1~5를 매번 별도 프로젝트로 만들지 않고 모듈을 재사용한다.

## 6. 사전 공개 통합 실습 — 4비트 미니 연산기

이 실습은 사전에 공개하는 기본 결과물이다. 14시에 공개하는 응용과제와 구분한다.

### 입출력과 동작

| 신호 | 폭 | 의미 |
|---|---:|---|
| a, b | 각 4비트 | unsigned 입력 0~15 |
| op | 2비트 | 연산 선택 |
| result | 4비트 | 연산 결과의 하위 4비트 |
| carry | 1비트 | 덧셈의 자리올림, 다른 연산에서는 0 |
| borrow | 1비트 | 뺄셈에서 a<b이면 1, 다른 연산에서는 0 |
| seg | 보드에 맞게 정의 | result의 한 자리 16진수 표시 |

| op | 연산 | 확인할 사항 |
|---|---|---|
| 00 | a+b | 하위 결과와 carry 분리 |
| 01 | a-b | 모듈로 16 결과와 borrow 분리 |
| 10 | a AND b | 비트 단위 연산 |
| 11 | a XOR b | 비트 단위 연산 |

보드에서는 스위치로 입력·연산을 선택하고, 결과는 한 자리 FND, carry·borrow는 LED로 표시한다. 실제 스위치 수와 FND의 정적 자리 선택 가능 여부를 확인한 뒤 핀을 확정한다. 인터페이스 제약이 있으면 입력 배치 또는 표시 방법을 수정하고 이 명세에도 반영한다.

### 검증 기준

- `op`, `a`, `b`의 조합 4×16×16=1024개를 자동 검사한다.
- 기준값은 요구사항에서 계산한다. DUT 내부 신호를 정답으로 사용하지 않는다.
- 파형에는 대표 정상 입력과 carry·borrow 발생 입력을 표시한다.
- 보드에서는 연산별 대표 입력과 경계 입력을 확인한다. 1024가지를 수동 조작하지 않는다.
- 값이 맞지 않으면 논리 오류, 테스트벤치 오류, 포트 연결, 핀·극성을 구분하여 기록한다.
