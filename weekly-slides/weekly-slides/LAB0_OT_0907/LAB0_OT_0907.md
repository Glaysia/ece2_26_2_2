# LAB 0. 오리엔테이션

전자전기컴퓨터설계실험Ⅱ · 2026. 09. 07. · 이해리

## 1. 이번 학기에 배우는 내용

이번 학기에는 FPGA와 MCU로 각각 기능을 구현하고, 두 장치를 연결해 팀 프로젝트를 진행한다.

- **FPGA:** Verilog HDL로 디지털 회로를 기술하고, 시뮬레이션과 합성을 거쳐 실제 보드에서 동작시킨다.
- **MCU:** C로 프로그램을 작성하고, 컴파일·다운로드하여 STM32에서 실행한다.
- **기능 활용:** 입출력, 타이머, PWM, 통신 등의 기능을 구현하거나 설정해서 사용한다.
- **장치 연결:** FPGA와 MCU 사이에 명령과 데이터를 주고받는다.
- **팀 프로젝트:** 필요한 기능을 나누어 구현하고, 통합한 시스템의 실제 동작을 검증한다.

### 도입 멘트 초안

> 이번 학기에는 두 종류의 보드를 사용합니다. FPGA에서는 Verilog로 회로를 구성하고, MCU에서는 C 프로그램으로 CPU와 주변장치를 사용합니다. 각각의 동작을 확인한 다음, 두 보드를 연결해서 여러분이 정한 기능을 구현하는 프로젝트를 진행합니다.

## 2. 왜 배워야 하는가?

### 전전컴 5개 분야에서 활용하는 기초

이번 과목에서 다루는 디지털 회로 설계, 펌웨어 작성, 통신과 계측은 다음 5개 분야의 장치 구현과 연결된다.

| 분야 | 연결되는 직무·응용 예 | 이번 수업에서 연습할 기초 |
|---|---|---|
| **반도체·회로·디스플레이** | 디지털 회로 설계·검증, 반도체 테스트·평가, 장비·디스플레이 제어 펌웨어 | HDL 논리 설계, 시뮬레이션과 파형 검증, 입출력 시험, 타이머·통신 |
| **전기·제어·로봇** | 전력변환·모터 제어, 로봇 제어, BMS 펌웨어 | 센서 입력, ADC·PWM·인터럽트, 조건 판단과 상태 제어 |
| **컴퓨터·디지털시스템** | XPU·SoC·네트워크 칩 설계·검증, FPGA 개발, 펌웨어·드라이버 개발 | 레지스터·FSM, 합성과 보드 검증, 주변장치 설정과 인터럽트 |
| **통신·신호처리** | 모뎀·신호처리 회로 구현, 통신장치 펌웨어 | 데이터 경로와 타이밍, 송수신, 데이터 형식과 통신 상태 제어 |
| **전파·광·양자** | 레이더·RF·광학 장비 제어, 광송수신 모듈 펌웨어, 양자 제어 전자장치 | 펄스와 동작 순서 제어, 장치 설정·상태 감시, 통신과 측정 인터페이스 |

분야별 전문 이론은 추가로 학습한다. 이번 학기에는 이러한 응용의 기초가 되는 **요구사항 정의 → 회로·프로그램 구현 → 실제 동작 검증**을 FPGA와 STM32로 연습한다.

### 발표 멘트 초안

> 관심 분야가 반도체인지, 로봇인지, 통신인지에 따라 만들 장치는 달라집니다. 하지만 그 안에는 데이터를 처리하는 회로, 장치를 제어하는 프로그램, 명령과 측정값을 전달하는 인터페이스가 있습니다. 이번 수업에서는 그 기능을 직접 구현하고 동작을 확인하는 경험을 쌓습니다. 전파·광·양자 분야에서도 장비의 타이밍을 제어하고 측정 결과를 읽는 전자장치와 연결됩니다.

### 배운 이론을 실제 장치에서 사용하기

디지털논리에서 배운 조합회로·레지스터·상태 머신을 FPGA에 구현한다. C와 마이크로프로세서에서 배운 내용을 MCU의 입출력과 주변장치 제어에 사용한다.

코드의 실행 결과를 화면에서 확인하는 데서 더 나아가, 보드의 핀에서 나오는 신호와 연결한 장치의 동작을 확인한다.

### 회로를 구성하는 방법과 프로그램으로 제어하는 방법 이해하기

예를 들어 일정한 주기의 신호를 만들 때, FPGA에서는 카운터와 비교 논리를 구성하고 MCU에서는 내장 타이머를 설정할 수 있다. 두 방법을 경험하면서 어떤 기능을 회로로 구현하고 어떤 기능을 프로그램과 주변장치로 처리할지 생각해 본다.

### 직접 동작을 확인하고 문제를 해결하기

실제 보드에서는 코드뿐 아니라 핀 연결, 설정값, 신호의 시간 관계도 결과에 영향을 준다. 원하는 동작을 정하고, 예상 결과와 실제 결과를 비교하며, 문제가 있는 부분을 찾아 수정하는 과정을 연습한다.

## 3. 수업은 어떻게 진행하는가?

이 부분에서는 학생이 매주 해야 할 일을 순서대로 설명한다.

1. 실험 목표와 필요한 기초 내용을 확인한다.
2. 예제 코드를 실행하고 요구사항에 맞게 수정한다.
3. 시뮬레이션 또는 디버깅으로 동작을 확인한다.
4. 실제 보드에서 실행하고 결과를 측정한다.
5. 조교에게 동작과 설계 내용을 설명한다.
6. 결과와 문제 해결 과정을 보고서로 정리한다.

첫 실습의 준비 범위, 이후 사전 과제, 팀별 수행과 개인별 제출의 구분을 이 부분에서 안내한다.

## 4. 무엇을 기준으로 평가하는가?

먼저 평가에서 확인할 내용을 설명하고, 점수와 제출 규정을 이어서 제시한다.

- 요구한 기능이 실제로 동작하는가?
- 테스트 조건과 결과가 요구사항을 확인하기에 충분한가?
- 자신이 작성·수정한 코드와 측정 결과를 설명할 수 있는가?
- 보고서에 설계 방법, 결과, 문제 해결 과정을 명확히 기록했는가?

### AI 사용 안내를 연결할 위치

AI 활용은 이 부분에서 함께 설명한다. 코드 작성에 도움을 받을 수 있지만, 제출한 설계의 동작을 확인하고 설명할 수 있어야 한다는 기준을 전달한다.

### 작성할 세부 규정

- 실험 확인 방식과 전체 성적 반영 비율
- 보고서 종류, 형식, 제출 기한, 감점 기준
- 소스코드와 작동 영상 제출 방법
- 인용과 표절 기준

보고서 세부 규정은 `../../../0906_보고서_채점_조건.md`를 기준으로 옮기되, 미확정 사항은 확정된 규정과 구분한다.
