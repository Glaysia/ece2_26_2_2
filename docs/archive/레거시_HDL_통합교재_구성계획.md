# 레거시 HDL 통합 프로젝트·TeX 교재 구성 계획

## 1. 목표와 범위

- 예전 교안을 단순히 합치지 않는다. 교육 내용을 정리하고 HDL을 다시 설계한 뒤, 검증한 코드와 파형을 바탕으로 교재를 작성한다.
- 하나의 프로젝트, 하나의 시뮬레이션 탑, 하나의 테스트벤치로 전체 실험을 확인한다.
- 탑모듈은 6개 주제별 모듈을 인스턴스화한다. 각 주제 모듈 아래에 작은 기능 모듈을 배치해 계층을 읽는 것 자체가 학습이 되도록 한다.
- 교재 본문은 하나의 `.tex`, 결과물은 목차가 있는 두꺼운 PDF 하나로 만든다. 기존 16:9 Beamer 템플릿을 그대로 사용한다.
- 개인 과제·학기 프로젝트·백업 기록은 제외한다. 장비 제공 코드 중 교안이 없는 예제도 보충 장으로 설명한다.
- 이 문서는 구현 계획이다. 아래 모듈명과 경로는 신설 예정이며, 아직 통합 동작이 검증된 상태가 아니다.

## 2. 원본과 재작성 코드 분리

작업 기준 경로: `example/fpga_projects_hdl/legacy_all_hdl/`

```text
legacy_all_hdl/
├─ vendor/                   # 비교·출처 확인용 원본, 통합 빌드에서 제외
├─ datasheets/               # 장비 제공 데이터시트
├─ src/
│  ├─ top_legacy.v           # 6개 주제 모듈의 연결과 명시적인 입출력
│  ├─ common/               # 공용 tick, 동기화 등 실제 공유하는 회로
│  ├─ combinational/        # 조합회로
│  ├─ sequential/           # 순차회로
│  ├─ display/              # 숫자·문자 표시
│  ├─ waveform/             # PWM·음원·모터 제어
│  ├─ fsm/                  # 상태 머신
│  └─ interface/            # UART·ADC·DAC·SRAM
├─ sim/
│  ├─ tb_legacy.sv          # 유일한 테스트벤치 진입점
│  └─ models/               # 필요할 때만 추가하는 외부 장치 동작 모델
├─ constraints/            # 검증한 보드용 XDC, 시뮬레이션과 분리
├─ scripts/                # 프로젝트 생성·컴파일·시뮬레이션·파형 설정
├─ .vscode/                # 통합 실행 태스크와 권장 확장
└─ build/                  # 생성 프로젝트·로그·VCD·WDB, Git 제외
```

- 기존 `.xpr`을 하나씩 고쳐 사용하는 대신, 상대경로 기반 생성 스크립트로 통합 프로젝트를 재현한다.
- 빌드 대상은 명시적인 파일 목록으로 관리한다. `vendor/`까지 재귀적으로 읽어 중복 모듈이 들어가는 일을 막는다.
- 기존 코드와 재작성 코드의 대응표를 남긴다: 원본 예제 → 새 모듈 → 교재 절 → 테스트 항목.

## 3. 탑모듈의 6개 하위 계층

```text
tb_legacy
└─ dut : top_legacy
   ├─ u_comb      : lab_combinational
   ├─ u_seq       : lab_sequential
   ├─ u_display   : lab_display
   ├─ u_waveform  : lab_waveform
   ├─ u_fsm       : lab_fsm
   └─ u_interface : lab_interface
```

| 계층 | 포함할 내용 | 주요 관찰 대상 |
|---|---|---|
| `u_comb` | NOT·논리 게이트, 반/전가산기·감산기, MUX/DEMUX, 인코더/디코더, 비교기, 4비트 산술 | 입력 조합, 선택 신호, 결과, carry/borrow |
| `u_seq` | 카운터, 업다운 카운터, 분주, 레지스터, 시프트 레지스터, PISO | reset, enable, count, 저장값, 직렬 출력 |
| `u_display` | BCD 변환, 7세그먼트 디코딩·자리 선택, 시계, 문자 LCD | 자릿값, segment, 자리 선택, LCD 제어·데이터 |
| `u_waveform` | LED/RGB PWM, 피에조·피아노, 스테핑 모터, 서보 | duty, 주기, 음원 출력, 모터 위상, 서보 펄스 |
| `u_fsm` | Moore, Mealy, 상태 응용, 신호등 | 현재/다음 상태, 전이 조건, 출력 차이 |
| `u_interface` | UART 계열 예제, ADC·DAC 인터페이스, SRAM | 송수신 데이터, 직렬 클록, 제어 신호, 버스 방향 |

- 6개 묶음은 단순 파일 보관함이 아니라 실제 하위 회로를 인스턴스화하는 모듈이다.
- 계층을 늘리는 것만을 위해 한 줄짜리 회로를 과하게 분할하지 않는다. 분할 기준은 기능·재사용·설명 가능성이다.
- `top_legacy`에는 입력뿐 아니라 각 묶음의 의미 있는 출력도 선언한다. 테스트벤치에서 내부 신호만 몰래 읽어 동작을 확인하는 구조로 만들지 않는다.
- 모든 묶음을 동시에 인스턴스화하고, 테스트벤치가 주제별 자극과 검사를 순서대로 수행한다. 매번 탑모듈의 주석을 바꿔 회로를 선택하지 않는다.
- FPGA 보드의 한정된 핀에 전체 실험 출력을 동시에 연결하지 않는다. 실제 보드 실습은 별도의 얇은 보드 래퍼와 출력 선택 회로로 처리한다. 시뮬레이션 DUT는 그대로 유지한다.

## 4. 코드 재작성 기준

- 설계 코드는 읽기 쉬운 Verilog `.v`, 테스트벤치는 SystemVerilog `.sv`를 기본으로 한다.
- 이름 있는 포트 연결, 명시적인 비트 폭, 짧고 의미 있는 신호 이름을 사용한다.
- 조합회로는 `assign` 또는 기본값이 있는 `always @*`, 순차회로는 비차단 대입 `<=`를 사용한다. 의도하지 않은 래치를 만들지 않는다.
- reset의 극성과 방식을 통일하고 교재 첫 부분에 정의한다. 원본과 동작이 달라지는 부분은 변경 이유를 기록한다.
- 내부의 느린 동작은 가능하면 단일 기준 클록과 clock enable/tick으로 처리한다. 분주기 자체를 배우는 예제의 분주 출력은 따로 보여준다.
- 버튼을 그대로 내부 클록으로 사용한 원본 등은 동기화·에지 검출 관점에서 재검토한다. 동기화와 디바운싱의 역할은 구분한다.
- 시간 상수·카운터 폭은 매개변수로 정의한다. 시뮬레이션 가속은 매개변수 변경으로 하되, 프로토콜의 타이밍 관계를 깨지 않는다.
- 공통 디코더·tick 생성기 등은 재사용한다. 같은 역할의 모듈을 예제마다 복사하지 않는다.
- 원본의 버그를 그대로 정답으로 싣지 않는다. 수정 전 현상·원인·수정 후 검증을 간단히 남긴다.
- VHDL 통합 데모는 참고 자료다. 같은 기능이 이미 있는 경우 중복 구현하지 않고, 필요한 고유 기능만 Verilog로 재구성한다.

## 5. 하나의 테스트벤치로 전체 검증

- 실행 경로: Vivado `xvlog → xelab → xsim`. Icarus는 사용하지 않는다.
- `tb_legacy.sv`에서 클록·reset을 생성하고, `test_comb`, `test_seq` 등 주제별 task를 호출한다. 외부 장치 모델은 별도 모듈이어도 테스트벤치 진입점은 하나다.
- 조합회로는 가능한 입력 조합을 전수 검사한다. 순차회로는 reset, enable, 방향 전환, 오버플로, 시프트 횟수 등 경계 조건을 검사한다.
- 출력이 맞는지 자동 비교해 성공·실패 개수를 남긴다. 실패하면 `$fatal`, 모두 끝나면 `$finish`로 종료한다. 별도 timeout도 둔다.
- 인터페이스는 UART 수신 검증, SRAM 응답 모델 등 필요한 상대 장치를 모델링한다. 단순히 핀이 토글되는 것만으로 통과시키지 않는다.
- ADC/DAC의 아날로그 성능이나 모터의 물리적 동작은 HDL 시뮬레이션으로 검증했다고 주장하지 않는다. 디지털 프로토콜 검증과 실제 장비 확인 항목을 구분한다.
- 전체 회귀시험과 주제별 짧은 실행을 같은 테스트벤치에서 선택할 수 있게 한다. 기본 실행은 전체 시험이다.
- VCD/WDB와 계층별 파형 보기 설정을 준비한다. 큰 전체 덤프 대신 촬영 시 필요한 주제·시간 구간으로 범위를 제한할 수 있게 한다.
- 촬영은 코드와 자동검증 결과를 확정한 다음에 진행한다. 지금은 찍지 않는다.

## 6. 단일 TeX 교재 목차

교재 파일: 이 문서와 같은 폴더의 `00.legacy_hdl.tex`.

1. 안내: 교재 범위, 원본 자료, 보드·Vivado 버전, 전체 실험 지도
2. 프로젝트 읽기: 파일 구조, 모듈과 인스턴스, 탑모듈의 6개 계층, 실행 방법
3. HDL 기초: 비트 폭, 연산자, 조합/순차 구분, 분기·반복이 회로로 표현되는 방식
4. 조합회로: 게이트 → 선택·변환 → 비교·산술 → 계층적 조합
5. 순차회로: 클록·reset → 레지스터 → 카운터·분주 → 직렬화
6. 표시 장치: BCD → 7세그먼트 → 다중화 → 시계 → 문자 LCD
7. 파형 생성과 구동: PWM → RGB → 음원 → 스테핑 모터·서보
8. 상태 머신: Moore·Mealy → 전이 검증 → 응용·신호등
9. 인터페이스 확장: UART, ADC/DAC, SRAM과 외부 장치 모델
10. 통합 검증: 전체 계층 탐색, 자동검사 결과, 파형 읽기, 대표 오류 디버깅
11. 부록: 보드 핀맵, 극성·전압·기준 클록, 원본 대응표, 참고문헌, 주요 코드 목록

각 실험 절의 순서는 다음으로 통일한다.

1. 무엇을 만드는가: 기능과 예상 입출력
2. 회로 구조: 블록도·포트·하위 모듈
3. 구현: 핵심 코드와 선택 이유
4. 검증: 입력 조건·예상 결과·자동검사
5. 파형: 표시할 신호·확인할 시간 구간·해석
6. 보드 적용: 핀맵·극성·주의점 및 실제 확인 여부

## 7. 편집과 출처 기준

- 기존 `weekly-slides/templates/weekly_presentation_template.tex`의 화면비·스타일을 사용한다. UOS Blue `#005EB8`, 시립대 로고, 저장소의 D2Coding을 유지한다.
- 교재 본문은 하나의 TeX에 `section`·`subsection`으로 구성한다. 전체 목차와 장별 목차, PDF 북마크로 탐색한다.
- 코드의 기준 원본은 `src/`와 `sim/`다. TeX에 코드를 다시 복사하지 않고 파일에서 필요한 구간을 불러온다.
- 긴 코드는 여러 프레임으로 나눈다. 폰트를 과도하게 줄여 한 장에 우겨 넣지 않는다. 전체 코드가 필요한 경우 부록에 나누어 수록한다.
- 코드 자체는 텍스트로 싣고, 실제 UI 설명·계층 탐색·파형에 스크린샷을 사용한다.
- 과거 Vivado 절차와 현재 검증 도구 버전을 명시한다. 구버전 교안 그림과 현재 UI를 같은 버전인 것처럼 섞지 않는다.
- 핀맵은 예제 XDC·보드 자료·부품 데이터시트를 대조한다. 충돌하거나 확인되지 않은 값은 추정으로 채우지 않는다.
- 교안에 없는 코드의 설명은 재구성한 설명임을 표시한다. 출처·라이선스·재배포 조건을 확인하고 참고문헌에 기록한다.

## 8. 작업 순서와 완료 기준

- [ ] 교안의 실험 목록과 장비 예제를 대조해 누락·중복·보충 주제를 확정한다.
- [ ] 모듈 대응표, 6개 묶음의 포트, 공통 clock/reset 규칙을 확정한다.
- [ ] 조합회로부터 새로 작성하고 자동검사까지 통과시킨다.
- [ ] 순차회로 → 표시 → 파형 생성 → FSM → 인터페이스 순으로 추가한다.
- [ ] 동일 프로젝트·동일 테스트벤치에서 전체 회귀시험을 한 번에 통과시킨다.
- [ ] 저장소를 다른 경로에 clone해 상대경로 빌드와 실행을 확인한다.
- [ ] 파형 계층·촬영 구간·파일명을 확정한 뒤 스크린샷을 촬영한다.
- [ ] 검증된 코드·파형 순서에 맞춰 단일 TeX를 작성한다.
- [ ] XeLaTeX 빌드 후 목차·참조·글꼴·넘침·핀맵·출처를 확인한다.

완료 기준은 “PDF가 생성됨”이 아니라 **교재의 예제를 동일 프로젝트에서 재현하고, 자동검사와 파형으로 설명을 확인할 수 있음**이다.
