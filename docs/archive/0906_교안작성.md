# 2026-09-06 FPGA 3주 교안 구성안

## 1. 이번 논의의 전제

- 대상은 C를 Visual Studio에서 작성해 본 정도이고, Verilog는 1학년 디지털논리 수업에서 짧은 예제를 접한 뒤 공백이 있는 학생이다. 사실상 처음부터 설명한다.
- 학생과 조교 모두 AI를 활용한다. 코드 작성 속도보다 요구사항을 정하고, 코드를 실행하고, 결과를 검증하는 능력을 중심에 둔다.
- 이번 문서는 FPGA 3주 분량의 제작 계획이다. STM32 3주와 이후 통합 프로젝트는 연결 방향만 정한다.
- 구 장비·신 장비·22년도 교안의 좋은 내용을 합친 뒤 중복을 제거하고, 그 통합본의 약 70%를 새 교안에 담는 것을 목표로 한다.
- 새 한 주는 기존 약 3주에 해당하는 내용을 묶는다. 모든 실습을 세 배로 부과한다는 뜻은 아니며, 설명·예제·검증·보충자료를 포함한 분량이다.

### 70%의 관리 방법

최종 제작 시 원본을 ‘설명할 개념 + 대표 예제 + 확인 질문’ 단위로 세분화한다. 중복 단위는 하나로 합친 뒤 유지·축약·보충·이관을 기록한다. 새 3주 교안의 본문과 보충에 들어가는 범위를 약 70%로 맞추되, 프로젝트 참고로 이관한 내용은 포함하지 않는다. 위 표는 선별 방향을 정하는 1차 목차이며 행 수를 세어서 70%라고 주장하지 않는다.

## 4. 3주 전체 구성

| 주차 | 제목 | 묶는 기존 내용 | 필수 결과물 |

## 5. 1주 상세안: Verilog와 조합회로

### 설명 순서

1. 스위치 입력과 LED 출력으로 디지털 회로의 입출력을 설명한다.
2. C 프로그램과 HDL의 차이, module과 포트, top module과 테스트벤치를 구분한다.
3. 제공된 프로젝트를 열어 AND 예제를 실행하고 입력 네 경우의 파형을 확인한다.
4. 비트·벡터·이진수·상수 표기를 설명하고 AND를 XOR로 바꿔 본다.
5. assign으로 조합논리를 표현하고, if/case를 쓰는 조합 always 블록으로 연결한다.
6. 반가산기와 전가산기로 내부 신호와 모듈 연결을 설명한다.
7. 다비트 덧셈에서 출력 폭과 carry를 확인한다.
8. MUX와 디코더를 설명하고 스위치·LED 또는 한 자리 FND로 확인한다.

### 실습과 통과 기준

- 따라 하기: AND/XOR의 네 입력 조합을 예상하고 파형과 대조한다.
- 필수 수정 실습: 제공된 4비트 연산·선택 회로에서 덧셈 결과와 XOR 결과를 선택하도록 완성한다. 가산기·MUX 골격과 테스트벤치는 제공한다.
- 확인: 선택 신호의 두 경우, 0 입력, 자리올림 발생 입력에서 예상값과 실제 출력이 일치한다. 보드에서 같은 입력을 확인한다.
- 보충: 전가산기의 구조적 구현, signed 비교, 인코더·DEMUX, FND 디코더 수정.

처음부터 빈 파일 작성을 요구하지 않는다. 설치 완료만 사전에 요청하고 첫 실행·시뮬레이션·보드 다운로드는 수업 안에서 함께 진행한다.

## 6. 2주 상세안: 클록·레지스터·카운터

### 설명 순서

1. 조합회로와 값을 기억하는 회로의 차이를 파형으로 비교한다.
2. 클록의 주기·주파수·상승 에지와 리셋을 설명한다.
3. DFF 한 개에서 레지스터로 확장한다. reg 선언 자체가 플립플롭을 뜻하지 않는다는 점을 다시 확인한다.
4. 순차 블록의 nonblocking 할당을 두 레지스터의 동시 갱신 예제로 설명한다.
5. 카운터의 증가·리셋·enable·최댓값 이후 동작을 확인한다.
6. 시스템 클록은 유지하고 일정 주기마다 enable을 만드는 구조를 설명한다.
7. 카운터 값을 LED 또는 제공 FND 표시 모듈로 내보낸다.
8. 버튼은 제공된 입력 처리 모듈을 통해 사용하고, 누름 상태와 한 번의 누름 이벤트를 구분한다.
9. 시프트 레지스터를 짧은 예제로 읽으며 다음 단계의 데이터 전달에 연결한다.

### 실습과 통과 기준

- 따라 하기: DFF·레지스터의 입력이 언제 출력에 반영되는지 예상한다.
- 필수 수정 실습: 일정 간격으로 증가하고 정지·재개·리셋이 가능한 카운터를 만든다. 타이밍 생성·버튼 처리·표시 모듈은 골격 또는 완성본을 제공한다.
- 확인: 리셋 값, 정지 중 유지, 재개 이후 증가, 최댓값 이후 동작을 파형에서 찾는다. 보드에서는 사람이 볼 수 있는 속도로 동작한다.
- 보충: up/down·parallel load, 시프트 레지스터, 피에조 또는 분·초 시계.

시뮬레이션에서는 작은 카운트 한계값을 사용하고 실물에서는 실제 클록에 맞는 값을 사용한다. 두 값의 차이를 학생이 설명하도록 한다.

## 7. 3주 상세안: FSM·PWM·통합

### 설명 순서

1. 카운터와 비교기를 연결하여 PWM의 주기와 duty를 설명한다.
2. 0%, 중간값, 100%를 어떻게 표현할지 요구사항부터 정한다.
3. 상태·입력·출력을 구분하고 간단한 상태도를 그린다.
4. 상태 레지스터와 다음 상태·출력 논리를 코드와 연결한다.
5. Moore를 기본 예제로 사용하고 Mealy는 비교 설명으로 둔다.
6. 정지·낮은 밝기·높은 밝기의 상태에 따라 PWM 설정을 선택한다.
7. 버튼 입력 처리, 상태 제어, PWM 생성, 표시를 top module에서 연결한다.
8. 시뮬레이션의 상태 전이·PWM 파형을 보드 계측 결과와 비교한다.

### 실습과 통과 기준

- 따라 하기: PWM 한 주기에서 high 구간의 길이를 세고 duty를 계산한다.
- 필수 수정 실습: 버튼을 한 번 누르면 모드가 바뀌는 3상태 PWM LED 제어기를 완성한다. 버튼 처리 모듈과 테스트벤치 골격을 제공한다.
- 확인: 리셋 직후 상태, 모든 상태 전이, 버튼을 계속 누른 경우, 모드별 duty, 실제 출력 주기를 확인한다.
- 보충: 신 장비 Lab-07의 `abaa` 패턴 검출, Mealy 비교, 피에조 출력, 다채널 PWM.

UART TX/RX 전체 설계는 이 3주 필수에 추가하지 않는다. 이후 STM32 통신 실습에서 검증된 통신 모듈을 제공하고, 이때 만든 PWM 설정 입력을 MCU가 바꾸도록 확장한다. 3주 종료 시 두 보드 통신까지 완성했다고 보지는 않는다.

## 8. 매주 4시간 운영안

| 활동 | 시간 | 운영 |

설치가 수업시간을 대부분 차지하지 않도록 사전 점검과 복구 안내를 제공한다. 진도가 밀리면 보충 실습을 생략하고 필수 결과물의 검증 시간을 확보한다.

## 9. AI와 함께 실습하는 방식

매번 ‘예상 → AI 도움으로 수정 → 실행 → 파형/계측 → 설명’ 순서를 반복한다.

- AI에 전달할 것: 모듈 입출력, 클록·리셋 조건, 요구 동작, 수정할 범위, 테스트 조건.
- 학생이 남길 것: 예상 결과, 실행 결과, 다를 때 바꾼 부분과 이유.
- 조교 질문 예: “이 한계값을 절반으로 바꾸면 주기가 어떻게 되나?”, “enable이 0이면 값이 왜 유지되나?”, “리셋 후 첫 상태가 어디인가?”
- 문법 전체 암기를 요구하기보다 짧은 수정과 결과 예측으로 개인 이해도를 확인한다.
- AI가 만든 테스트벤치도 설계와 같은 오해를 가질 수 있으므로, 진리표·손계산·명시한 상태 전이를 기준값으로 사용한다.

## 10. 제작할 때 교정할 부분

- 22년도 「처음 실습하기」는 p.4의 SW_A/SW_B 역할 설명과 p.28 핀 표의 배치가 서로 다르다. 원본 핀 표를 그대로 복사하지 않는다.
- 같은 자료 p.27 등에 `LVCMOSS33` 표기가 보인다. 새 교안의 제약 파일은 실제 보드용으로 검증된 파일을 기준으로 작성한다.
- 버튼을 직접 클록으로 사용하는 기존 예제는 새 기본 예제로 삼지 않는다. 보드 클록과 처리된 버튼 이벤트를 구분한다.
- 기존 게이트 피드백 DFF 과제를 초보자 필수에서 빼고 에지 기반 순차 블록으로 설명한다.
- 기존 테스트벤치의 무한 반복, 출력 신호의 암묵적 선언 등은 그대로 옮기지 않는다. 명시적 신호 선언과 종료 조건을 갖춘 예제로 작성한다.
- 에디터 진단, 시뮬레이션, 합성·보드 다운로드를 구분해서 안내한다. 실행 도구의 확정은 현재 저장소 설정을 확인한 후 별도로 하며, 예전 설치 지시를 재사용하지 않는다.
